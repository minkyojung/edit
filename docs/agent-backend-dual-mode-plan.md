# 에이전트 백엔드: 구독 + 자체 하네스 겸용 설계 메모

작성일: 2026-07-15

## 목표

제품이 선택에 따라 **구독 기반(공식 CLI)** 또는 **자체 하네스(API 키 직접)** 로
모델을 굴릴 수 있게 한다. 제품 코드는 어느 쪽인지 몰라야 한다.

## 배경 개념

- **하네스** = 모델 출력을 실제 행동(툴 실행)으로 바꾸고, 결과를 다시 모델에
  되먹여 반복시키는 오케스트레이션 코드. (루프 + 툴 + 컨텍스트 관리 + 안전장치)
- **구독**(Claude Pro/Max, Codex 구독)은 공식 클라이언트에 OAuth로 묶여 있음.
  자체 레이어에서 구독을 직접 API처럼 쓰는 건 약관 위반. 대신 **공식 CLI를
  서브프로세스로 감싸면** 구독을 합법적으로 쓸 수 있다.
- **자체 하네스**는 API 키로 모델을 직접 호출하고 루프/툴/컨텍스트를 직접 구현.

"자체 하네스 완전 구현 + 구독 그대로 + 합법" 세 개를 동시에 만족하는 길은 없다.
그래서 두 백엔드를 나눠 두고 상황에 맞게 고른다.

## 구조

```
   [제품 UI / 오케스트레이터]
            │
      ┌─────┴─────┐
      │ AgentBackend │   ← 공통 인터페이스 (하나)
      └─────┬─────┘
      ┌──────┴───────┐
      ▼              ▼
 [구독 백엔드]     [자체 하네스 백엔드]
 공식 CLI 래핑      API 키 + 에이전트 루프
 (claude/codex)    (직접 구현)
```

핵심은 **하나의 추상 인터페이스** 뒤에 두 백엔드를 꽂는 것. 두 백엔드가
똑같은 **이벤트 스트림**을 내보내면 제품은 둘을 구분하지 못한다.

## 인터페이스 (계약)

```ts
interface AgentBackend {
  send(prompt, context): stream of events
  // 이벤트 종류: 텍스트, 툴호출요청, 툴결과, 완료, 에러
  cancel()
  getContextUsage()
  capabilities()   // 이 백엔드가 뭘 지원하는지
}
```

- **구독 백엔드**: CLI stdout(JSON stream)을 파싱해 공통 이벤트로 **번역**.
  툴 실행·컨텍스트는 CLI가 알아서 함.
- **자체 하네스 백엔드**: 자기 루프에서 공통 이벤트를 **직접 발생**.

## 미리 알아야 할 함정

두 백엔드는 능력이 다르다. 이걸 인터페이스에서 어떻게 다룰지가 진짜 난이도.

- **툴** — 구독 백엔드는 CLI가 가진 툴 위주(커스텀 툴 주입 제한적).
  자체 하네스는 자유롭게.
- **권한/승인** — 승인 흐름이 CLI마다 다름.
- **컨텍스트 회계** — 자체 하네스는 정확, 구독 CLI는 안 알려주기도 함.

→ 대응: `capabilities()`로 지원 여부를 노출하고, UI가 그에 맞춰 켜고 끈다.

## 진행 순서

1. **자체 하네스 하나만** 제대로 만든다 → 거기서 나오는 이벤트·툴·컨텍스트
   개념으로 인터페이스를 역으로 뽑아낸다.
2. 인터페이스가 굳으면 → 구독 백엔드를 그 인터페이스에 맞춘 **번역기**로 붙인다.

처음부터 둘을 동시에 추상화하면 잘못된 인터페이스가 나온다.
하나를 깊게 만들고 계약을 추출하는 게 정석.

> 참고: 제품이 이미 Claude Code SDK/CLI를 쓰고 있다면 구독 백엔드는 사실상
> 이미 있는 셈. 다음 스텝은 그 호출부를 `AgentBackend` 인터페이스 뒤로
> 감추는 리팩터부터.
